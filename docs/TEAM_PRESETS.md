# Team presets (ISL 2026-27)

Reusable, season-scoped team data — club, head coach, full squad, official logo/headshot URLs — that fills both teams when you create a match. Everything here is read from the official league website by a maintenance command; nothing is hard-coded in the app.

## At a glance

| | |
|---|---|
| Target season | **Indian Super League 2026-27** (the site's fixtures name it `Indian Super League, 2026-27`, series id 944; the same series id tags every squad page) |
| Imported | **13 teams, 366 players, 13 head coaches** (read 2026-10-12) |
| Source | https://www.indiansuperleague.com — public club switcher, fixtures, club squad pages and player profile pages |
| User-facing entry | Library → **Create from ISL teams** (`/new`) → ISL presets / Custom teams |
| Data files | `public/presets/index.json`, `public/presets/isl/2026-27.json` (served statically) |
| Audit trail | `docs/presets/isl-2026-27-import-report.md` (regenerated by every `--apply`) |
| Hand corrections | `data/presets/isl/2026-27.overrides.json` (survive every refresh) |

## What a user sees

1. **Create match** screen with two choices: **ISL presets** or **Custom teams** (the existing blank-match flow, unchanged — the library's *Create match manually* button still works as before).
2. ISL presets: one card per club (crest, official name, abbreviation, home city, head coach, squad size, season). Choose one **Home** and one **Away**; the same club cannot be both. *Create match* is disabled until both are chosen.
3. The match opens in the normal workspace. Each team has its name, coach and the **whole registered squad in a "Squad pool"**; the XI and bench are **empty** and the formation is the default. The user moves players *To XI* / *To bench* exactly as when adding players by hand, can edit names/numbers/positions, add their own players, and return players to the pool.
4. Everything downstream (formations, board, arrows, clock, goals/subs/cards, replays, export/import, undo) is the existing code on the existing `Match`.

If the data has not been imported the screen says so, shows the command to run, and offers no fake teams.

## Data model

### Reusable side (`src/domain/presets/types.ts`)

```
SeasonPresets   league {id,name}, season "2026-27", generatedAt, generator, sources[], teams[]
  TeamPreset    id "isl-club-656" (season-independent), sourceId, officialName, displayName,
                shortName|null, abbreviation|null, city|null, venue|null, logoUrl|null, profileUrl|null,
                coach CoachPreset|null, players[], verification, notes[], source {url, retrievedAt}
    CoachPreset   name, role, nationality|null, photoUrl|null, verification, notes[], source
    PlayerPreset  id "isl-player-19150" (from the source's player id, so a transfer keeps the identity),
                  sourceId, name, displayName|null, shirtNumber|null, position|null
                  (Goalkeeper/Defender/Midfielder/Forward), nationality|null, dateOfBirth|null (ISO),
                  headshotUrl|null, profileUrl|null, verification, notes[], source {url, retrievedAt}
```

* `verification`: `official` (read from an official page), `manual` (supplied by hand with a source, or an override), `unverified`.
* Unknown values are `null`, never guessed. `notes` records anything odd the importer saw (a number published as `-1`, a profile naming the player differently, a club named differently on two pages).
* One file per league + season. A new season is a new file; a player who moves club keeps the same `isl-player-<id>` in the next season's file, and old seasons are never rewritten.

### Match side (`src/domain/types.ts`, persisted schema v4, all new fields optional)

```
Team.preset?   presetId, league, season, snapshotAt, verifiedAt, officialName, shortName, abbreviation,
               city, logoUrl, profileUrl, coach {name, photoUrl}        — snapshot of the preset team
Team.pool?     Player[] (≤ 60): registered players not in the matchday squad
Player.origin? presetId, season, imported {name, shirtNumber|null, position}, sourcePosition,
               nationality, dateOfBirth, photoUrl, profileUrl           — snapshot of the preset player
```

### Integrity rules

* **Snapshot, never a link.** Creating a match copies the data with fresh ids (`snapshotTeam`). Editing a match cannot change a preset; refreshing a preset cannot change an existing match; players who later leave or transfer stay in historical matches. (Tests: `snapshot.test.ts`, `Presets.test.tsx` "independent of later preset updates".)
* **`Team.players` is still the matchday squad** (≤ 22: 11 starters + 11 substitutes). ISL clubs register ~25–36 players, so the rest live in `Team.pool`; promoting from the pool is subject to the same capacity and shirt-number rules as adding a player. Pool players do not appear on the board or in event forms.
* **Imported vs corrected vs added.** `Player.origin.imported` keeps the imported values: the UI shows **Corrected** when name/number/position were changed, **Added by you** for players without an origin, **Number missing** when the source gave no usable number (a temporary one, counting down from 99, was assigned — correct it in Edit).
* **Duplicate numbers published by the source are kept** (East Bengal #8, #34; Kerala Blasters #26; Punjab #11; Sporting Club Delhi #8, #18, #99). The pool tolerates them; moving the second one into the squad explains the clash and asks you to change one number.
* **Positions are coarse.** The site publishes only Goalkeeper / Defender / Midfielder / Forward; they map to GK / CB / CM / ST as the *preferred* position, and the UI shows the source word. Change them in Edit; formation slots are not assigned automatically.

## How the initial data was collected

All with `npm run presets -- fetch --profiles --apply`, which:

1. Reads `robots.txt` and refuses any URL it disallows (the site disallows `/api/*`, `/apiv3/*`, `/user`, `/login`, `/profile`; club, squad and player pages are allowed). It never calls those API paths.
2. Reads the home page's club switcher (13 clubs) and the fixtures page, from which it takes the season label (`2026-27`), each club's official abbreviation, and confirms the club set.
3. Reads each club's `/squad` page. The server-rendered HTML contains the squad widget data (names, nationality, position, number) plus the cards (headshot, profile link) and the Head Coach card. Each squad's series id must map to the requested season, otherwise the import is blocked.
4. With `--profiles`, reads each player's profile page for the date of birth (`DD-MM-YYYY` on the site → ISO).
5. Normalises, validates against the schema, runs the quality checks, diffs against the current file and — only with `--apply` — writes the files and the report.

Politeness: one request per second (more if robots.txt asks), a generic user agent with no personal data, raw pages cached in the git-ignored `.cache/presets/` so re-runs are free, one retry on 5xx, and it **stops** with a pointer to the manual import on 401/403/429 — it never tries to get around an access control. The whole run is 16 requests without `--profiles` (robots.txt, home, fixtures, 13 squads) and 16 + one per player with it (≈ 6 minutes for 366 players).

I did not locate a terms-of-use page on the site (the usual legal URLs redirect to the home page; the footer says "© Indian Super League – All Rights Reserved"). The importer therefore takes only facts shown on public pages, at a low rate, and treats images as copyrighted (below).

## Commands

```bash
# Preview (writes nothing): what would change, warnings, blocking errors
npm run presets -- fetch --profiles

# Write public/presets/** and docs/presets/<league>-<season>-import-report.md
npm run presets -- fetch --profiles --apply

# Quick refresh without re-reading profiles (dates of birth already on file are kept)
npm run presets -- fetch --apply

# Options: --season 2026-27  --refresh (ignore cache)  --offline (cache only)
#          --delay-ms 1500  --cache-dir DIR  --force (rewrite although the data is unchanged)

# Check the committed files again
npm run presets -- validate [--file public/presets/isl/2026-27.json]
```

Exit code is non-zero when the data is invalid or there are blocking errors (duplicate team/player ids, a player listed for two clubs, a squad that does not belong to the season). Warnings (gaps) never block.

### Refreshing squads and coaches

Run the preview, read the *Changes against the current file* block, then `--apply`. The diff lists coach changes, players added (and "joined from X"), players no longer listed (and "now listed for X" when they moved inside the league), renumbering and changed image URLs. Existing matches are never touched — they hold snapshots.

### Supplying data by hand (no website access, or a club the site cannot give you)

**CSV** — one row per player; team columns repeat on every row of a team; `source_url` is mandatory on every row so the data stays auditable.

```csv
team,abbreviation,city,venue,logo_url,coach,coach_photo_url,player,shirt_number,position,nationality,date_of_birth,headshot_url,profile_url,source_url
Test United,TU,Testville,Test Park,,Jane Coach,,"Doe, John",9,Forward,India,1999-01-02,,,https://club.example/squad
Test United,TU,Testville,Test Park,,Jane Coach,,Sam Keeper,1,Goalkeeper,Spain,,,,https://club.example/squad
```

```bash
npm run presets -- import --file squads.csv --league isl --season 2026-27          # preview
npm run presets -- import --file squads.csv --league isl --season 2026-27 --apply
```

Positions must be Goalkeeper, Defender, Midfielder or Forward; dates `YYYY-MM-DD`. Ids are derived from the names (`isl-club-test-united`, `isl-player-test-united-doe-john`). **JSON** — a complete `dizpitch.teampresets` file (same shape as `public/presets/isl/2026-27.json`) passed with `--file season.json`. A manual import **replaces only the teams it contains** and leaves the rest of the season alone, so one club can be added or corrected without re-importing the league. Rows/records are marked `verification: "manual"`.

### Correcting a value the source gets wrong or omits (overrides)

Put it in `data/presets/isl/2026-27.overrides.json`; it is re-applied after every import and listed in the report (and flagged when the source later agrees, so you can delete it):

```json
{
  "format": "dizpitch.presetoverrides",
  "schemaVersion": 1,
  "league": "isl",
  "season": "2026-27",
  "teams":   { "isl-club-2354": { "city": "Varanasi", "reason": "Home city per the club's own site", "source": "https://…" } },
  "players": { "isl-player-19150": { "shirtNumber": 11, "reason": "Confirmed by the club", "source": "https://…" } }
}
```

Allowed team fields: `displayName, shortName, abbreviation, city, venue, logoUrl, coachName`; player fields: `name, shirtNumber, position, nationality, dateOfBirth, headshotUrl`. A `reason` is required. The shipped file is empty: no value was added without a source.

### Adding a new season or league

* **Next ISL season:** `npm run presets -- fetch --season 2027-28 --profiles` (the importer refuses if the site's fixtures do not show that season, so it cannot silently import the old one), then `--apply`. The manifest lists both seasons and the Create match screen offers a season selector.
* **Another league:** use the manual import with `--league <id> [--league-name "…"]` and a CSV/JSON; add a parser under `src/presets/<league>/` if it has a scrapeable site, and set its expected team count in `scripts/presets.ts`.

## Jersey display (kit themes)

On the Board, **Circles | Jerseys** (next to the orientation toggle, also in fullscreen) draws players as simplified shirts, seen from behind, with the squad number printed on the back. The control is offered only when at least one team was created from a preset that has a kit theme; custom teams keep circles (in a preset-vs-custom match only the preset side wears jerseys). The choice is saved with the match (`Match.playerDisplay`, schema v5, absent = circles). Switching only changes how markers are drawn: positions, selection, formations, arrows, events and replays are untouched. Replays (AI sketches and tracked replays) use the same jerseys when the match is in jersey mode.

- **Kit themes** live in `src/domain/presets/kits.ts`, keyed by preset team id (so every match made from a preset gets them, including ones created before this feature). A theme has primary, secondary, optional accent, number colour, outline, a pattern (`solid`, `halves`, `stripes`, `panel`, `gradient`, `piping`), optional collar/sleeve colours and an optional gradient. All are deterministic; hex values are our approximations of the named colours, **not official brand values**, and the designs are original simplified vectors, not retail shirts or sponsor artwork.
- **Kit choice** per side (`Team.kit`, `home | away`, absent = automatic): automatic = home kit, but the away side switches to its away kit when the two shirts are too similar (CIE76 ΔE < 30). A club without a documented away kit gets a generic stand-in (light shirt with the club colour as trim), labelled as such in the Kits panel.
- **Numbers**: a shirt number is printed only for a known number. A preset player the source gave no number (`origin.imported.shirtNumber === null`) carries a *temporary* number for the squad rules; while it is unchanged (`origin.assignedNumber`) the jersey shows no number and the marker's label omits it. Tracker ids are never printed as shirt numbers.

## Images and licensing

* Logos and headshots are the league's/clubs' copyrighted material. **They are not downloaded, bundled, proxied or stored** — only their official URLs are kept, and the browser fetches them from the league's own CDN when a card or row is shown (lazy, `no-referrer`).
* Only `https` URLs on the allow-list in `src/domain/presets/images.ts` (currently `www.indiansuperleague.com`) are ever requested, which also stops a hand-edited or imported match file from pointing an `<img>` at another server. Add a host there deliberately if you import data with images from elsewhere.
* No permission to re-use the images was found. If you need to be certain, set **`NEXT_PUBLIC_PRESET_IMAGES=off`** (build/dev time): no image request is made and every crest/headshot is the abbreviation/initials fallback. Everything works the same.
* Headshots are ~350 KB PNGs. They are lazy-loaded and cached by the browser (the CDN sends a one-year `cache-control`), but opening a 36-player pool the first time downloads them as you scroll.
* Fallbacks cover: no URL, a blocked host, a slow request (the fallback shows until the picture arrives), and a failed one (the fallback stays). Aspect ratios are handled with fixed boxes (`contain` for crests, `cover` anchored to the top for portraits).
* Images are not drawn on the SVG pitch, so PNG export of the board is unaffected.

## Known gaps in the 2026-27 data (all recorded in the report)

| Gap | Count | Notes |
|---|---|---|
| Team short name | 13 | The site publishes only an abbreviation (e.g. `BFC`); `shortName` is `null` unless you supply one |
| Home city | 1 | Inter Kashi: the site gives no venue line. "City" is the last part of the venue line as printed, so it is sometimes a region (`Goa`, `Delhi`) |
| Date of birth | 30 | Profile pages whose server-rendered HTML carries no biography (mostly new registrations); the importer does not call the site's data API for them |
| Nationality | 9 | Not published for those players |
| Shirt number | 1 | Aman CK (NorthEast United) is published as `-1`; the match gets a temporary number and a **Number missing** badge |
| Duplicate numbers | 7 | Listed on the official page for two players each (see above) |
| Names | 4 | The profile page uses a nickname form (e.g. "Franchu Abalo" vs "Francisco Feuillassier Abalo"); the squad page's full name is used |
| Positions | all | Only the four coarse categories exist |

I have **not** verified the data against a second source; "official" means "as published on the league's own pages on 2026-10-12". Squad pages change — re-run the preview before an important match.
